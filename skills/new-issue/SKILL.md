# New Issue

Record a TODO, bug, or feature request as a GitHub issue.

## Classify by Label

Assign exactly one label:

- `enhancement`: Feature requests, improvements, or TODOs.
- `bug`: Broken behavior that needs to be fixed.

## Less Burden

Write in plain language for fast human reading, and go straight to the point.

If the target repository has its own issue template or guidelines, follow its structure while keeping the rules in this skill.
Otherwise, include only the sections below (omit optional parts when not applicable):

### `enhancement`

- **What we want**: The desired behavior or change.
- **Context**: Why it is needed or what problem it solves.
- **Prior art** _(optional)_: How other projects handle it.

Don't mention implementation details.

### `bug`

- **What happened**: Actual behavior or error output.
- **What was expected**: Expected behavior.
- **Steps to reproduce**: Minimal steps or command to trigger the bug.

Don't suggest solutions.
